# 后台分批删除与共享资料保护

日期：2026-11-20。版本：`0.3.27-opt.5-resumable-delete`。

## 问题与行为

此前的 60 秒保护能取消长期持锁的删除，但大型探索图在时限内删不完时会整笔回滚，反复点击仍从头开始。本次将任务页删除改为持久化后台作业。`DELETE /api/tasks/{id}` 在停止任务、等待 Agent 和侧边会话退出后，短事务保存删除计划、设置 `deleted_at` 并暂停任务，返回 HTTP 202 和 `cleanup_pending`、`cleanup_job_id`。任务移出列表后，后台继续执行，不依赖浏览器保持连接。

提交删除后会逐批永久清理，不提供整项撤销。重复提交同一任务会返回已有作业，不改变原清理选项。其他任务及模型、提示词、经验策略不因此调整。

## 清理流程

`停止并移出任务 → 独有流量 → 无引用流量文件 → 独有资产 → 活动记录 → 独有报告 → 探索节点 → 可选模型记录 → 任务及探索表 → 可选工作文件`

- `task_cleanup_jobs` 保存任务和探索编号、清理选项、候选资产、候选主机、流量快照边界、当前阶段和计数。表不依赖任务外键，任务物理删除后仍可查询清理结果。
- 通常每批删除 1,000 条活动、100 个节点、100 个资产或 50 个报告；每批数据库事务最多 5 秒，等锁最多 500 毫秒。超时重试会缩小当前批次。
- 图记录和任务文件清理不持有全局资产/关联表锁。流量和资产阶段仅在短批次内锁定归属相关表，重新判断共享关系；不在这些锁内执行整个探索图的级联删除。
- 最后的探索表删除使用事务内的索引查询偏好，避免大量活动删除后旧统计信息仍使外键检查扫描整张活动表；不修改全局数据库设置。
- 每批数据库删除和进度在同一事务提交。进程中断后读取已提交位置继续，不重做整个任务。连续 5 次失败后暂停作业，任务页显示错误和“重试”。重试继续当前阶段。
- SQLite 流量删除使用时间与行号快照边界，只处理排队前的捕获记录；删除计数与 SQLite 回执一并提交。PostgreSQL 进度提交失败时，重放不会丢失或重复计算流量计数。
- 文件使用精确任务目录和 `exp<id>-` 转录前缀分批清理，不沿符号链接进入其他目录。空间整理沿用后台回收机制，作业结束不等于磁盘已经归还全部空闲页。

## 共享资料

共享判断涵盖 `assets.task_ids`、探索节点资产关联和 `task_asset_links` 归属记录。其他保留任务通过任一种方式引用资产，都会保留该资产。流量按完整主机名保护：另一任务通过任何资产引用相同主机，保留该主机的全局流量。每批重新检查，覆盖排队后新增共享关系的情况。

其他任务共用漏洞组的报告成员会保留；保留此类报告时也保留该任务工作文件，避免删除报告附件。无法从 SQLite 排除历史磁盘引用时，延后对应 blob 的物理回收并返回说明。Token 历史账本继续保留。

## 可见状态与接口

任务页增加“清理进度”，显示阶段、活动和节点处理计数、错误及重试入口。HTTP 202 表示已接收删除，`state=done` 才表示后台流程完成。

- `GET /api/task-cleanups`：最近的清理作业及进度，不返回内部候选计划。
- `POST /api/task-cleanups/{id}/retry`：恢复失败的清理作业。

旧 `Manager.DeleteTaskContext` 同步方法及其 60 秒取消保护保留，供兼容调用和原有回归使用；任务页 API 已切换到后台作业。

## 验证

七项新增回归覆盖流量快照与回执、共享 blob、批次取消、跨批次恢复、重复提交、独有资产/报告/工作文件删除、共享归属记录、排队后新增共享、共享报告及附件、符号链接隔离、旧格式流量目录在提交后的恢复。PostgreSQL 回归仅在显式启用的 localhost 独立测试数据库运行，使用合成资料，不访问测试目标。

traffic、db、server 相关新旧回归通过，前端 TypeScript 检查与静态发行构建通过，嵌入前端的 Go 发行构建通过。不宣称全仓库测试通过，也不把存储修复当作漏洞发现收益。
